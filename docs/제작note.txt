[0] 인프라 / 환경 (배포·로컬 전환)
────────────────────────────────────────────────────────────────
● 배포 후 로그인 실패("백엔드(9001) 실행 여부 확인") 원인 = FE가 브라우저에서
  http://localhost:9001 을 호출 → 접속 PC 자신의 localhost를 찾아 실패.
● 해결: FE API 주소를 "접속한 host 기준 런타임 자동 해석"으로 변경.
  - home/src/lib/api.ts, admin/src/lib/auth.ts 에 resolveServiceUrl(env, port, fallback) 추가.
    env(NEXT_PUBLIC_*) 지정 시 우선, 없으면 window.location.host + 지정포트(9001/3100/8001).
  - home/.env.local, admin/.env.local 의 하드코딩 IP 주석 처리(자동감지 우선).
  → localhost로 열면 localhost, 서버IP로 열면 서버IP로 자동 동작(파일 수정 불필요).
  * 전제: FE·admin·BE가 같은 host에서 서비스될 때. 다른 host면 env로 고정.

● Java 버전: be/pom.xml <java.version> 25 → 17 로 수정(로컬 JDK가 Temurin 17이라
  "release version 25 not supported" 빌드 실패했었음). 서버도 Java 17+ 필요.

● 로컬 작업 전환: application.yml datasource 기본값을 원격→로컬로.
  - DB_HOST 기본 localhost, DB_USER 기본 chin4_test (로컬은 chin4 계정 없음, chin4_test/1234 존재),
    CORS allowed-origin-patterns = localhost,127.0.0.1.
  - 원격 전환 시엔 코드 수정 없이 환경변수만: DB_HOST=175.125.94.198, DB_USER=chin4.
  * ⚠ BE가 원격 DB에 붙으면 ddl-auto=update 스키마 변경 + DataSeeder 계정 시드가 원격에 실행됨(주의).

● [2026-07-23] 서버에서 로그인 시 "서버 연결 실패(백엔드 9001 확인)" 재발 → 원인은 CORS.
  - FE는 host 자동해석으로 http://175.125.94.198:9001 을 정상 호출하나, BE의
    app.cors.allowed-origin-patterns 가 localhost,127.0.0.1 만 허용 → 서버IP Origin
    (http://175.125.94.198:8001) preflight 403 → 브라우저가 응답 차단 → fetch throw →
    login page.tsx catch 블록의 "서버 연결 실패" 메시지 표출(실제론 CORS 거부).
  - 해결: application.yml
      allowed-origin-patterns: ${CORS_ORIGINS:http://localhost:*,http://127.0.0.1:*,http://175.125.94.198:*}
    (localhost 유지 + 서버IP 추가, CORS_ORIGINS 환경변수로 오버라이드 가능)
  - 검증: 서버IP:8001/:3100/localhost:8001 Origin preflight 모두 200 + Access-Control-Allow-Origin 정상.
  - ★ 서버 반영하려면 be 재패키지/재배포(또는 서버 BE 재기동) 필요. 코드에 이미 반영됨.
  - 구분법: 서버 브라우저 개발자도구 Network에서 login 요청이
      · "CORS error"/차단 → 위 문제(이번 수정으로 해결)
      · "connection refused"/무응답 → BE 미기동 또는 9001 포트 미개방(방화벽) 확인.

● 실행: 루트 start-all.ps1 (be/home/admin), stop-all.ps1.
  - 특정만: .\start-all.ps1 be  (be|home|admin)
