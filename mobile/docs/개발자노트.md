# 친비즈 모바일 앱 (PWA + 웹푸시) — 개발자 노트

기존 chinbizERP_V3 웹을 **모바일 앱(PWA)** 으로 제공한다. 별도 앱 코드베이스 없이 **admin(Next.js) 앱에 PWA를 얹었다.**
- **설치**: 안드로이드 Chrome에서 `admin.chinbiz.kr` → "홈 화면에 추가" (스토어 심사 불필요)
- **알림**: 웹표준 **Web Push + VAPID**(Firebase 불필요). 회원별 타게팅.
- **자동 업데이트**: 서비스워커가 실시간 웹을 로드(네트워크 우선) → 웹 수정이 앱에 즉시 반영.

## 구성 요소

### 프론트엔드 (admin/)
- `admin/public/manifest.webmanifest` — PWA 매니페스트(이름/아이콘/standalone).
- `admin/public/sw.js` — 서비스워커. ①네트워크 우선(HTML 항상 최신, `/api`·`/uploads`는 미개입) ②`push`→알림표시 ③`notificationclick`→해당 워크스페이스 이동.
- `admin/public/icons/*.png` — 앱 아이콘(192/512/maskable). **임시 생성본 → 실제 로고로 교체 권장.**
- `admin/src/app/layout.tsx` — manifest·theme-color·아이콘 메타 + `<PushManager/>` 전역 마운트.
- `admin/src/components/pwa/PushManager.tsx` — SW 등록 + 알림권한 요청("🔔 알림 켜기") + 구독을 BE에 저장.
- `admin/src/app/login/page.tsx` — admin 자체 로그인(PWA를 admin 오리진 하나로 완결). `lib/auth.ts`의 `goToLogin()`이 여기로 이동.

### 백엔드 (be/, `com.chinbiz.api.push`)
- `PushSubscription` / `PushSubscriptionRepository` — 구독 저장(테이블 `push_subscription`, endpoint UNIQUE).
- `PushController` — `GET /api/push/vapid-public-key`(공개), `POST /api/push/subscribe`, `DELETE /api/push/unsubscribe`.
- `WebPushService` — `nl.martijndwars:web-push`(+BouncyCastle)로 VAPID 암호화 발송. `sendToAccounts(accounts, title, body, url)`. 만료(404/410) 구독 자동 삭제.
- 설정: `application.yml` `app.push.vapid.{public-key,private-key,subject}` (env `PUSH_VAPID_*`로 override).

### 알림 발생 지점(푸시 트리거) — **2곳**
1. **이벤트 알림(핵심)** — `AlarmService.fire()`. ERP의 모든 알람(가입·영업 SALE1/SALE2·취소·정산 마감/정산/지급·교육·매니저 승급·상품등록·파트너상담)이 이 관문을 지난다.
   인앱 `alram` 저장과 **동시에** 수신자 본인(`recipient.id`)에게 웹푸시 발송 → **특정 회원 타게팅**이 자동으로 됨.
2. **공지사항** — `NoticeController.create/update`. 발행 시 대상(역할/센터, `NoticeRecipientResolver`)에게 웹푸시.

## VAPID 키

Web Push는 **VAPID 키쌍**으로 인증한다(Firebase 불필요). 최초 1회 생성 후 고정.
- 현재 `application.yml`에 **개발용 기본 키**가 들어 있어(= jwt.secret 처럼) 바로 동작한다.
- **운영 배포 시** 새 키를 생성해 환경변수로 주입 권장(기본 키 노출 방지):

```bash
npx web-push generate-vapid-keys
```

출력된 Public/Private 키를 환경변수로 설정(윈도우 PowerShell 예):
```powershell
$env:PUSH_VAPID_PUBLIC_KEY  = "<공개키>"
$env:PUSH_VAPID_PRIVATE_KEY = "<개인키>"
$env:PUSH_VAPID_SUBJECT     = "mailto:admin@chinbiz.kr"
.\mvnw.cmd -DskipTests spring-boot:run
```
> 키를 바꾸면 **기존 구독은 모두 무효화**되어 회원이 다시 알림 허용을 해야 한다.

## 로컬 테스트

1. BE 기동: `cd be && mvnw.cmd -DskipTests spring-boot:run` (9001). 로그에 `[push] WebPushService 초기화 완료` 확인.
2. admin 기동: `cd admin && npm run dev` (3100).
3. 데스크톱 Chrome에서 `http://localhost:3100/login` 로그인 → DevTools > Application 에서 **Manifest / Service Workers** 등록 확인.
   - `localhost`는 서비스워커·푸시가 HTTP에서도 허용(예외). 실서버는 **HTTPS 필수**.
4. 로그인 후 **🔔 알림 켜기** → 권한 허용 → `push_subscription` 테이블에 row 저장 확인.
5. 알림 발생시키기:
   - **공지**: 본사(MASTER_ADMIN)로 대상 공지 발행 → 대상 구독자에게 알림 도착.
   - **이벤트**: 해당 회원이 관련된 영업/정산/교육 등 프로세스 트리거 → 그 회원에게 알림 도착.
6. 앱(탭)을 백그라운드로 두고도 알림이 오는지 확인.

## 주의 / 향후

- **HTTPS 필수**(실서버). `admin.chinbiz.kr` SSL 준비되어 있음(deploy/nginx). `/sw.js`·`/manifest.webmanifest`는 admin(3100)이 정적 서빙.
- **iOS**: 16.4+ 홈 화면 PWA만 푸시 가능·제약 큼 — 현재 범위 밖(안드로이드 우선).
- **성능**: `AlarmService.fire()`의 푸시 발송은 현재 동기(요청 스레드). 대량 브로드캐스트(예 PRODUCT_REGISTER 전체 버즈)에서 지연 가능 → 필요 시 @Async/큐로 비동기화(현재 예외는 격리되어 알람 저장엔 영향 없음).
- **아이콘**: `admin/public/icons/*.png` 는 임시 생성본(골드 "친"). 실제 브랜드 로고로 교체.
